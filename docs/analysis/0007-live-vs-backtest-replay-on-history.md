# 0007 — Прогон истории через live-код: расхождения времени сессии в backtest

Дата: 2026-10-03. Продолжение [0006](0006-null-model-finds-three-more-biases.md). Код — после
правок модели исполнения 0005/0006.

## Контекст

Совпадение live и backtest проверялось на 8 сделках (0005). Мало, чтобы поймать редкие ветки:
границы сессии, пересечение слотов на одном тикере, дневной сброс. Нужна сверка на всей истории.

## Метод

1. **Чтение кода**: три боевые стратегии (ORC/session ORC, OR Fade, MF) и три пути исполнения.
2. **Нулевая модель на всех 6 слотах**: боевой конфиг на синтетическом мартингале 07:00–23:50 МСК
   (700 дней, 3000 шагов на бар, ~18 б.п. на бар, случайный объём), slippage 0.
   `mf-afternoon` с боевым порогом пробоя (0.77%) на мартингале не торгует — гонялся с порогом 0.05%.
3. **Прогон истории через live-методы** `SelfManagedStrategy` (`processCandle`, `checkSLTP`,
   `trailOnBar`, `checkEOD`, `checkDailyReset`) с тем же `VirtualExecutor` и `GlobalRiskController`,
   что у backtest. Внутри бара — тики по пути O→худший→лучший→C с интерполяцией, на закрытии —
   свеча с `now` = конец бара + 1 с. Поштучная сверка с `eval.RunPortfolioBacktest` по ключу
   (слот, тикер, направление, бар входа).
4. **Санити данных** `data/history`: порядок, дубли, OHLC-согласованность, нули, гэпы — чисто.

## Находки

1. **Вечерняя сессия ночевала в backtest.** EOD проверялся по началу бара; у `session-orc-evening`
   (eod 23:50) последний бар начинается в 23:45, бара с началом ≥ 23:50 нет — позиция переезжала
   через ночь: **27 сделок из 156, удержание до 62 ч**, выход на утреннем гэпе. В live её закрывает
   таймер EOD в 23:50.
2. **Время решения в backtest — начало бара, в live — конец.** Отсюда: EOD на 5 минут позже
   (по close бара 18:40–18:45 вместо цены 18:40); вход на баре, заканчивающемся ровно на eod
   (**28 сделок только в backtest**); стратегия видела другой набор баров (live передаёт бар,
   закончившийся в момент открытия, и не передаёт бар, закончившийся на eod) — отсюда разный ATR
   и разные уровни тейка при одинаковом входе.
3. **Дневной сброс** в портфельном backtest шёл по часам первого по алфавиту слота (`mf-afternoon`,
   10:00) для всех слотов и портфельного контроллера; в live каждый слот сбрасывается по своей
   сессии, контроллер — первым открывшимся (утро, 07:00). `GlobalRiskController.ResetDaily` к тому же
   очищает список открытых позиций — сброс при открытой позиции снял бы занятость тикера.
4. **Бары одной метки обрабатывались тикер за тикером**: вход по A на закрытии бара видел открытой
   позицию по B, закрытую внутри того же бара. Теперь в два прохода: выходы по всем тикерам, потом входы.
5. Мелочь: backtest по тикеру не подставлял тикер слота в заявку без тикера (portfolio и live — да).

## Не ошибки, но знать

- **Приоритет слотов на одном тикере в live недетерминирован**: два слота хотят тикер на одном
  баре — берёт тот, чья горутина успела первой. Backtest — по алфавиту ключа слота. При сверке
  порядок надо выравнивать, иначе ~85 ложных расхождений.
- **Стратегия видит бар, только когда у слота нет позиции и вход разрешён по времени.** История
  стратегии — с дырами, зависящими от её же сделок; у `mf-afternoon` (вход с 12:30) «диапазон за
  39 баров» в начале окна захватывает вчерашний день. Одинаково в live и backtest, но смысл
  параметров плывёт. Кандидат на правку при переподборе.
- Дневной лимит убытка в backtest считает валовой PnL, в live — после комиссии. Лимит в 2% депозита
  почти не срабатывает.
- **ORC для реальной торговли**: ретест-лимит «исполняется» задним числом по закрытому бару; на бирже
  это должна быть заявка, выставленная на закрытии бара пробоя (см. 0006).
