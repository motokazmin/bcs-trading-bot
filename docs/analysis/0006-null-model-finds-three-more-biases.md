# 0006 — Нулевая модель: ещё три заглядывания вперёд в симуляторе

Дата: 2026-10-03. Продолжение [0005](0005-closed-bar-fix-live-matches-backtest.md); код — рабочее
дерево после правок 0005 (тейк в баре фила не засчитывается, отмены лимита ORC по close нет).

## Контекст

Ошибки симулятора находились поштучно, по одной за круг разбора. Нужен детектор, который
ловит заглядывание вперёд, не зная, где оно: стратегия без преимущества обязана давать
ноль до издержек. Если она в плюсе — плюс выдаёт симулятор.

## Метод

- `random_entry` получил лимитный режим (`limit_offset_atr`, `limit_expiry_bars`): заявка
  позади цены на offset·ATR, исполнение как у ретест-лимита ORC. Иначе null-модель не
  проходит лимитный путь, где сидели ошибки 0005.
- Выход — блок `orc-complement` (тейк 1.225R, трейл 0.364R / 4 стадии), slippage 0,
  мерится `Trades[].PnLR` (в backtest — до комиссии).
- **Реальные данные null-модель не судят:** при внутридневной инерции выход по трейлу
  честно зарабатывает и при случайном входе. Поэтому — синтетика: мартингал из посекундных
  шагов (3000 на бар, ~12 б.п. на бар), собранный в M5 OHLC. На нём матожидание любой
  стратегии ровно 0. Генератор — `gen_synth2.py` (scratchpad сессии; при переносе в тест
  переписать на Go).

## Находки

1. **Трейл внутри бара.** Путь `O → худший экстремум → лучший → C`: стоп подтягивается на
   лучшем экстремуме, а возврат к худшему после этого не проверяется. Модель держит позицию
   через просадку, про которую «знает», что цена вернётся к close. +0.05R на чистом мартингале.
   Стресс `-intrabar-oscillations 2` перекашивает в обратную сторону (−0.12R) — тоже не модель.
   Честно: трейл пересчитывается по закрытому бару, внутри бара стоп фиксирован.
2. **Фил стопа на гэпе.** `closePosition` во всех трёх путях повторно зовёт `ExitFillPrice`,
   и стоп всегда исполняется по уровню, даже если бар открылся за ним. Видно по разбивке:
   выходы по безубытку давали ровно +0.056R, без единого хуже. Честно: по худшему из стопа и open
   (в live — из стопа и тика).
3. **Гейт входа по close бара фила** (`tradeaudit.ValidateOpen`: `LIMIT_VS_CLOSE`, `ENTRY_PAST_STOP`
   по `BarClose`). Ставился в 0001, когда фил писался по цене, которой не было. При честном
   филе он выкидывает сделки, к закрытию бара уже ушедшие против позиции. ~+0.06R на синтетике.

Остаток −0.03R у лимитного входа с тейком — консервативная сторона модели (при касании стопа и
тейка в одном баре засчитывается стоп). При выходе только по стопу он исчезает. Оставлен
сознательно: ошибка в худшую сторону.

## Статус

**Внесено в код 2026-10-03** во всех трёх путях (live/virtual, backtest по тикеру, портфельный):
- трейл — по закрытому бару (`position.TrailPrice`, в live `trailOnBar`), внутри бара стоп фиксирован;
- выход по open бара / по тику — `position.ExitFillPriceAt` (худшее из стопа и цены);
  `closePosition` больше не перезаписывает цену исполнения уровнем;
- гейт входа снят: `LIMIT_VS_CLOSE` и `ENTRY_PAST_STOP` — пометки (warn), `Rejects()` удалён;
- `-intrabar-oscillations` удалён — с фиксированным внутри бара стопом он ничего не меняет.

Держат `TestTrailMovesOnBarCloseAndGapFillsAtOpen` (runner и portfolio), `TestTrailMovesOnClosedBarOnly`
(live), `TestCheckSLTPStopLossFillsAtWorseOfStopAndTick`, `TestValidateOpenCloseBasedCodesAreWarnings`.
Мутацией проверены трейл и фил на гэпе во всех трёх путях. Итоговый backtest совпал с прототипом:
+0.034R, PF 1.07. Последние полгода (2026-04→10): −0.079R.

## Последствия

- ORC при честной модели преимущества не имеет. Оставшийся плюс портфеля — `or-fade` и `mf-afternoon`,
  оба со входом по close, и оба мало проверены (`or-fade` деградирует, у `mf-afternoon` 45 сделок).
- **Архитектурная дыра ORC для реальной торговли:** стратегия решает по закрытым барам, а ретест-лимит
  «исполняет» внутри бара задним числом. В реальной торговле это должна быть настоящая заявка на бирже,
  выставленная на закрытии бара пробоя. Сейчас live выставил бы её уже после того, как цена прошла уровень.
- Детектор работает: поймал три перекоса, о которых не было гипотез. Следующий шаг — сделать его
  тестом на Go-синтетике, чтобы новая дыра ловилась до оптимизации.
