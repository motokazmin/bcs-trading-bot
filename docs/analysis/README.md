# Разбор сделок: как хранится и как читается

Цель — чтобы через месяц (и в новой сессии с Claude) можно было за одну команду
понять: что уже проверено, что отвергнуто, и двигаются ли метрики.

## Что читать первым

1. **`docs/analysis/state.md`** — текущее состояние: активные гипотезы, что уже
   закрыто и почему. Один файл, всегда актуальный.
2. **`data/analysis/metrics.csv`** — журнал прогресса. Одна строка = (снимок, эксперимент).
3. Отдельные разборы — `docs/analysis/NNNN-*.md`, ADR-стиль: контекст → решение → последствия.
   Не переписываются: если вывод устарел, добавляется новый файл со ссылкой на старый.

## Как снять срез

```bash
make analyze LABEL="после фикса фила"
```

Скрипт `scripts/analyze-trades.py` читает `data/trades.db` + `data/history/*.csv` и пишет:

| Файл | Что внутри | Режим |
|------|-----------|-------|
| `data/analysis/trades_enriched.csv` | сделки + производные метрики, одна строка на сделку | перезаписывается |
| `data/analysis/metrics.csv` | срез по экспериментам: дата, git rev, label, метрики | **append-only** |

`metrics.csv` дописывается, а не перезаписывается — в этом весь смысл. Сравнение
двух снимков показывает, помогла правка или нет.

## Метрики, которых нет в БД

БД знает только то, что видел бот. Эти считаются по историческим барам постфактум
и отвечают на вопрос «была ли у сделки вообще возможность сработать»:

| Метрика | Смысл | Плохо, когда |
|---------|-------|--------------|
| `pos_at_open_r` | где позиция на открытии следующей 5-мин свечи | медиана < 0 — систематически входим против движения |
| `dead_on_arrival_share` | доля сделок уже за стопом сразу после входа | > 0.1 — модель исполнения врёт |
| `same_bar_share` | доля сделок, открытых и закрытых в одной свече | > 0.2 — стоп внутри шума или вход мусорный |
| `fillbar_close_r` | где закрылась свеча, в которой записан фил | сильно < 0 — фил зафиксирован по цене, которой не было |
| `level_touched` | прошёл ли рынок уровень пробоя в свече входа | `False` — сигнала не должно было быть |
| `median_r_bps` | размер стопа в б.п. от цены | < 30 — R внутри спреда и тика |
| `left_on_table_r` | сколько R осталось после выхода до конца сессии | стабильно > 1 — выход рубит победителей |

## Порядок работы

1. Прогнать бота/бэктест → сделки копятся в `data/trades.db`.
2. `make analyze LABEL="что изменилось"` → снимок в `metrics.csv`.
3. Если вывод содержательный — отдельный файл `docs/analysis/NNNN-*.md` и строчка в `state.md`.
4. Метрики читать вместе с `docs/baseline.md`: расхождение бэктеста и live — самостоятельный
   диагностический сигнал, а не шум.

## Чего эти цифры не доказывают

- Меньше ~200 сделок — статистики нет ни на что, кроме грубых поломок механики.
  Механику (`dead_on_arrival_share`, `same_bar_share`) видно и на 50 сделках;
  edge (`expectancy_r`) — нет.
- `left_on_table_r` — идеальный максимум задним числом. Он показывает, что выход
  рубит движение, но не сколько из этого реально забирается.
- Контрфактические прогоны по тем же данным, что породили сигналы, всегда оптимистичны.
